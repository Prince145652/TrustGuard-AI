# NEAR Smart Contract Deployment Guide

This guide provides step-by-step instructions for building, testing, and deploying the **TrustGuard Security Registry** smart contract to the **NEAR Protocol Testnet**.

---

## 1. Smart Contract Overview

The TrustGuard registry is written in **Rust** using the official `near-sdk` (v5.1.0). It acts as a tamper-evident audit ledger that stores cryptographic fingerprints (SHA-256) of security reports generated by TrustGuard AI.

### Storage Layout & State:
- `reports_by_hash`: `LookupMap<String, ReportRecord>` — Maps each 64-character hex SHA-256 report hash to its immutable on-chain record.
- `reports_by_id`: `LookupMap<String, String>` — Secondary index mapping human-readable Report IDs (e.g. `TG-EVM-9A4B8F`) to their canonical hash.
- `total_reports`: `u64` — Running counter of all verified reports registered on NEAR.
- `contract_owner`: `AccountId` — The administrator account initializing the contract.

### Key Methods:
| Method Name | Type | Description |
|-------------|------|-------------|
| `register_report` | Change (Call) | Registers a new security report hash. Validates 64-hex format, prevents duplicate collisions, records block height and nanosecond timestamp. |
| `verify_report` | View | Returns `true` if a report hash exists and is valid on-chain; returns `false` otherwise. |
| `get_report` | View | Returns the full `ReportRecord` for a given SHA-256 hash. |
| `get_report_by_id` | View | Resolves a Report ID to its full `ReportRecord`. |
| `get_total_reports`| View | Returns the total count of reports anchored on NEAR. |

## 3. Local Compilation & Unit Testing

Before deploying to the blockchain, run the built-in unit tests to ensure everything works properly:

```bash
cd /home/prince/agy-demo/contracts/trustguard-registry

# Run cargo unit tests
cargo test
```

You should see all 3 unit tests pass:
- `test_register_and_verify` (registers and asserts `verify_report` returns true)
- `test_duplicate_registration_fails` (ensures reports cannot be overwritten)
- `test_invalid_hash_length_fails` (rejects non-64-character hashes)

### Compiling to WebAssembly (Wasm)
Compile the contract into a standalone `.wasm` binary optimized for the NEAR Virtual Machine:

```bash
cargo build --target wasm32-unknown-unknown --release
```

The compiled binary will be generated at:
```
target/wasm32-unknown-unknown/release/trustguard_registry.wasm
```

## 4. Deploying to NEAR Testnet

### Step 1: Login or create your deployer account
Ensure you have a funded NEAR Testnet account (e.g., `trustguard-auditor.testnet`):

```bash
near login
```

### Step 2: Deploy the compiled Wasm binary
Deploy the `.wasm` file to your contract account:

```bash
near deploy \
  --accountId trustguard-auditor.testnet \
  --wasmFile target/wasm32-unknown-unknown/release/trustguard_registry.wasm
```

### Step 3: Initialize the Contract
Call the initialization function `new()`:

```bash
near call trustguard-auditor.testnet new '{"owner_id": "trustguard-auditor.testnet"}' --accountId trustguard-auditor.testnet
```

## 5. Testing Deployed Contract via CLI

### A. Register an Audit Report (Change Call)
```bash
near call trustguard-auditor.testnet register_report '{
  "report_id": "TG-WAL-TEST01",
  "report_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "target": "0x742d35Cc6634C0532925a3b844Bc454e4438f44e",
  "scan_type": "WALLET",
  "risk_score": 12,
  "risk_level": "LOW"
}' --accountId trustguard-auditor.testnet --gas 30000000000000
```

### B. Verify the Report (View Call - Free, No Gas)
```bash
near view trustguard-auditor.testnet verify_report '{
  "report_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}'
# Output: true
```

### C. Retrieve Report Details (View Call)
```bash
near view trustguard-auditor.testnet get_report '{
  "report_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}'
```

## 6. Updating the Web Application

Once your contract is deployed to Testnet, update your `.env.local` file:

```bash
NEAR_NETWORK_ID="testnet"
NEAR_NODE_URL="https://rpc.testnet.near.org"
NEAR_CONTRACT_ID="trustguard-auditor.testnet"
```

Restart your Next.js application (`npm run dev`), and all verification queries will automatically read live data directly from your deployed contract on the NEAR blockchain!
